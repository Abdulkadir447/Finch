Chapter 11 — API Specification
11.1 Purpose

This chapter defines the API architecture, standards, endpoints, request/response formats, authentication, versioning, and communication protocols used by Finch.

Unlike traditional web applications, Finch is an offline-first desktop application, meaning APIs are used primarily for:

User authentication
Cloud synchronization
AI services
License activation
File uploads
Email integration
Future mobile support

All APIs are implemented as Supabase Edge Functions or Supabase REST endpoints.

11.2 API Design Goals

The API must be:

Fast
Secure
Stateless
Versioned
Easy to maintain
Strongly typed
Well documented
Backward compatible

11.5 API Versioning

Every endpoint begins with an API version.

Example

/api/v1/

Future

/api/v2/

Versioning prevents breaking existing clients.

11.6 Authentication

Every protected endpoint requires

Authorization: Bearer <access_token>

The token is issued by Supabase Authentication.

Unauthenticated requests return

401 Unauthorized
11.7 Standard Headers

Request

Content-Type: application/json

Authorization: Bearer <token>

Accept: application/json
11.8 Standard Response

Every endpoint returns the same format.

Success

{
    "success": true,
    "data": {},
    "error": null
}

Failure

{
    "success": false,
    "data": null,
    "error": {
        "code": "INVALID_INPUT",
        "message": "The provided data is invalid."
    }
}

11.33 OpenAPI Documentation

Every endpoint must be documented using the OpenAPI 3.1 specification.

Documentation should include:

Endpoint description
Request schema
Response schema
Authentication requirements
Error responses
Example requests and responses

The API documentation should be automatically generated and version-controlled.

11.34 Acceptance Criteria

The API layer is considered complete when:

All endpoints follow RESTful conventions.
Authentication is required for protected resources.
Responses follow the standardized format.
Endpoints are versioned.
OpenAPI documentation is complete.
Rate limiting and validation are implemented.
Performance targets are met.
Security requirements are enforced.
Chapter Summary

This chapter defines Finch's API architecture, covering REST endpoints, authentication, versioning, request/response standards, and integrations with Supabase, OpenAI, storage, synchronization, and Gmail. The API is designed to be secure, scalable, and maintainable while supporting Finch's offline-first desktop architecture and future expansion.
