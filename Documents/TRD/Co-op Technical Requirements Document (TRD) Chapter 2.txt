Chapter 2 — Technology Stack & Development Environment
2.1 Purpose

This chapter defines the complete technology stack, development environment, tooling, package management strategy, dependency standards, project structure, and local development workflow for Co-op.

Its purpose is to ensure that every developer works in a consistent environment and follows the same technical standards throughout the project lifecycle.

2.3 Technology Selection Principles

Every technology selected for Co-op must satisfy the following requirements:

Long-term community support
Strong documentation
TypeScript compatibility
Active maintenance
Production stability
High performance

Low technical debt

Experimental technologies should not be introduced into production without evaluation and approval.

2.7 Package Manager

Co-op uses pnpm.

Reasons:

Faster dependency installation
Efficient disk usage
Strict dependency resolution
Excellent monorepo support
Deterministic lockfile

All developers must use the same pnpm-lock.yaml file.

2.11 Environment Variables

Sensitive values must never be hardcoded.

Example:

VITE_SUPABASE_URL=

VITE_SUPABASE_ANON_KEY=

SUPABASE_SERVICE_ROLE_KEY=

OPENAI_API_KEY=

LOG_LEVEL=

Rules:

Client applications may only access public environment variables.
Secrets must remain server-side.
.env files must not be committed to version control.

2.13 Versioning Strategy

All packages follow Semantic Versioning.

Format:

MAJOR.MINOR.PATCH

Example:

1.0.0

Rules:

MAJOR: Breaking changes
MINOR: New features
PATCH: Bug fixes
2.14 TypeScript Configuration

TypeScript operates in Strict Mode.

Key settings:

strict: true
noImplicitAny: true
strictNullChecks: true
noUnusedLocals: true
noUnusedParameters: true
noFallthroughCasesInSwitch: true

Use of the any type should be avoided and justified when necessary.

Branch naming convention:

Commit messages follow Conventional Commits.

Examples:

docs: update architecture guide

test: add AI service tests

chore: update dependencies
2.20 Development Standards

Developers must:

Use feature branches.
Write meaningful commit messages.
Keep pull requests focused.
Avoid direct commits to main.
Resolve linting and type errors before submission.
Update documentation when introducing architectural changes.
2.21 Coding Conventions

General conventions:

Prefer functional components.
Use named exports unless a default export is justified.
Keep files focused on a single responsibility.
Avoid deeply nested logic.
Use descriptive names.
Minimize side effects.
Centralize configuration.
2.22 Folder Naming

Use lowercase kebab-case.

Examples:

inventory-management/

customer-list/

report-generator/

Avoid:

InventoryManagement/

CustomerList/

ReportGenerator/
2.23 File Naming
File Type	Convention
React Components	PascalCase (OrderTable.tsx)
Hooks	camelCase with use prefix (useOrders.ts)
Utilities	camelCase (formatCurrency.ts)
Constants	UPPER_SNAKE_CASE where appropriate
Types	PascalCase (Order.ts)
2.24 Dependency Update Policy

Dependencies should be reviewed monthly.

Guidelines:

Apply security patches promptly.
Test all updates in a development environment.
Avoid upgrading major versions immediately after release.
Document breaking changes before adoption.
2.25 Documentation Requirements

Every module must include:

README (where applicable)
Public API documentation
Type definitions
Usage examples for shared packages
Comments for complex algorithms

Documentation is considered part of the implementation.

2.26 Development Checklist

Before marking a feature complete:

Code compiles successfully.
Type checking passes.
Linting passes.
Tests pass.
Documentation updated.
No unnecessary dependencies added.
Performance impact reviewed.
Security considerations addressed.

Chapter Summary

This chapter establishes the technical foundation for Co-op by defining the approved technology stack, development tools, repository organization, coding conventions, dependency management, and local development workflow. Adhering to these standards ensures consistency, maintainability, and scalability across the entire codebase.

The technologies selected—including Electron, React, TypeScript, Vite, Supabase, SQLite, and the OpenAI Responses API—provide a robust platform for building an offline-first, AI-powered business management application.
