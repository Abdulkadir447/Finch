Chapter 12 — Database Schema & Data Dictionary
12.1 Purpose

This chapter defines the complete database schema for Finch Version 1.0.

It serves as the single source of truth for every database object used by the application, including:

SQLite Local Database
Supabase PostgreSQL Database
Table definitions
Relationships
Constraints
Indexes
Data types
Views
Triggers
Naming conventions
Entity relationships

SQLite and PostgreSQL use nearly identical schemas to simplify synchronization.

12.2 Database Architecture
                 Finch Desktop

              SQLite Database
                    │
          Sync Engine (Offline First)
                    │
              Supabase PostgreSQL

SQLite is the operational database.

Supabase PostgreSQL acts as the synchronized cloud database.

12.24 Database Views

Version 1.0 includes several read-only views.

sales_summary

Aggregated sales by day, week, month, and year.

inventory_status

Current stock levels with low-stock indicators.

customer_statistics

Customer lifetime value, order count, and average order value.

profit_loss_summary

Revenue, costs, gross profit, expenses, and net profit.

dashboard_metrics

Optimized dataset for the dashboard widgets.

Views reduce complex query logic in the application layer.

12.28 Migration Strategy

Database schema changes use versioned SQL migrations.

Example:

001_initial_schema.sql
002_products.sql
003_orders.sql
004_reports.sql
005_ai_history.sql
006_notifications.sql

Rules:

Migrations are immutable.
Applied in ascending order.
Tracked in a migration history table.
Backward-compatible whenever possible.
12.29 Data Dictionary Standards

Each table and column must include documentation describing:

Business purpose
Data type
Allowed values
Validation rules
Relationships
Default values

This documentation should be maintained alongside the schema and updated with every migration.

12.30 Acceptance Criteria

The database schema is considered complete when:

All business entities are represented.
Relationships are enforced through foreign keys.
Constraints maintain data integrity.
Indexes support performance targets.
Views simplify reporting.
Triggers automate critical workflows.
SQLite and PostgreSQL schemas remain synchronized.
Migrations are version-controlled and reproducible.
Chapter Summary

This chapter defines the complete database schema and data dictionary for Finch. It establishes standardized table structures, relationships, constraints, views, triggers, and migration practices across both SQLite and Supabase PostgreSQL. The schema is optimized for an offline-first architecture while ensuring data integrity, synchronization reliability, and future scalability.
