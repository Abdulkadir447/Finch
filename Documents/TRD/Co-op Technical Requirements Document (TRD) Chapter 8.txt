Chapter 8 — Authentication, Authorization & Licensing
8.1 Purpose

This chapter defines the authentication, authorization, session management, identity security, and software licensing architecture for Co-op.

The authentication system ensures that only authorized users can access Co-op, while the licensing system verifies that the software has been legitimately activated. Together, these systems protect user data, support offline-first operation, and enable secure access to cloud services.

8.2 Design Goals

The authentication and licensing systems must achieve the following objectives:

Secure user authentication
Reliable offline operation
Strong identity protection
Secure software licensing
Automatic session management
Easy account recovery
Future support for multiple users and organizations
Minimal user friction

8.8 Token Management

Supabase issues:

Access Token
Refresh Token

Rules:

Refresh automatically before expiration.
Never expose tokens in logs.
Never send tokens through IPC unless required.
Destroy tokens immediately on logout.
8.9 Secure Token Storage

Authentication tokens must not be stored in SQLite.

Instead, they should be stored using secure operating system facilities.

Windows:

Windows Credential Manager
DPAPI (Data Protection API)

This protects credentials even if the database is copied.

8.25 Security Policies

Authentication security includes:

TLS 1.3 encryption
Secure token storage
Password hashing (handled by Supabase Auth)
Rate limiting on login attempts
Email verification
Mandatory HTTPS
CSRF protection where applicable
Secure IPC communication
8.26 Failed Login Protection

Protection mechanisms:

Progressive delays after repeated failures
Temporary account lockout after excessive attempts
Audit logging
Administrator notifications (future)

These controls help mitigate brute-force attacks.

8.27 Account Recovery

Recovery methods:

Password reset email
2FA recovery codes
Email verification

Future versions may include administrator-assisted recovery for multi-user organizations.

8.28 Licensing Security

Activation keys should:

Be cryptographically generated
Never follow predictable sequences
Be validated only by secure backend services
Never be hardcoded in the application

License verification should occur through Supabase Edge Functions.

8.29 Acceptance Criteria

Authentication and licensing are considered complete when:

Users can securely register and log in.
Sessions persist correctly.
Tokens are stored securely.
Password recovery functions correctly.
Two-factor authentication is operational.
Licenses activate successfully online.
Activated licenses continue functioning offline.
Authorization rules are enforced consistently.
Security events are logged appropriately.

Chapter Summary

This chapter defines Co-op's identity and licensing framework using Supabase Auth for secure authentication and online activation keys for software licensing. By combining encrypted local session storage, two-factor authentication, secure token management, and offline-capable licensing, Co-op provides a secure and reliable user experience while supporting future expansion into multi-user and enterprise environments.
