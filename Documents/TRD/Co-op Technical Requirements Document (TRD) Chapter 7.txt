Chapter 7 — Database Architecture & Offline Synchronization
7.1 Purpose

This chapter defines the data architecture of Co-op, including the local SQLite database, the cloud PostgreSQL database on Supabase, synchronization mechanisms, repository implementations, migration strategies, conflict resolution, backup systems, and data integrity policies.

The database architecture is designed around an Offline-First philosophy. Every business operation is written locally before being synchronized with the cloud, ensuring uninterrupted use even when internet connectivity is unavailable.

7.2 Database Philosophy

Co-op follows four core principles:

Local First – All writes occur in SQLite first.
Cloud as Synchronization Layer – Supabase acts as the authoritative cloud replica for synchronization, authentication, and cross-device support.
Eventual Consistency – Local and cloud databases will converge automatically after synchronization.
Data Integrity – No operation should result in silent data loss.

7.18 Conflict Resolution Strategy

Resolution priority:

Automatic merge (non-overlapping fields)
Latest valid update
User decision (complex conflicts)

Example:

Inventory Quantity

Local = 24

Cloud = 27

Co-op should notify the user when automatic reconciliation is not possible.

7.19 Retry Strategy

Failed synchronization uses exponential backoff.

Example:

Retry 1 → 5 sec

Retry 2 → 15 sec

Retry 3 → 30 sec

Retry 4 → 60 sec

Retry 5 → Manual Review

Infinite retry loops are prohibited.

7.29 Encryption at Rest

Sensitive local data should be encrypted, including:

Authentication tokens
License information
API configuration
Cached AI context

The SQLite database may remain unencrypted in Version 1.0, but sensitive fields must use operating system–level secure storage (such as Windows Credential Manager) where appropriate. Full database encryption is planned for a future release.

7.34 Acceptance Criteria

The database architecture is considered complete when:

All business operations function offline.
Synchronization reliably updates Supabase.
Conflicts are detected and resolved appropriately.
Transactions maintain data consistency.
Backups and restores are successful.
Performance targets are met.
Database migrations are repeatable.
Data integrity is preserved under failure conditions.
Chapter Summary

This chapter defines Co-op's offline-first database architecture, combining SQLite for fast, reliable local storage with Supabase PostgreSQL for secure cloud synchronization. By using repositories, transactions, migration management, synchronization queues, and conflict resolution, the data layer ensures resilience, consistency, and scalability while allowing users to continue working regardless of network availability.
