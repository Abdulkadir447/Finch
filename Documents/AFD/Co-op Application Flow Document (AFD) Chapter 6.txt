Chapter 6 — Orders & Invoice Management Flow
6.1 Purpose

This chapter defines the complete lifecycle of an order in Co-op, from creation to completion, invoice generation, payment tracking, cancellation, and returns.

The Orders module is one of the most critical workflows in Co-op. Every action taken within this module directly affects:

Inventory
Customers
Reports
Revenue
AI Insights
Forecasting
Dashboard KPIs
Cloud Synchronization

The workflow is designed to minimize manual work while maintaining complete data accuracy.

6.2 Objectives

The Orders module must:

Allow fast order creation.
Support draft orders.
Prevent inventory inconsistencies.
Generate professional invoices.
Integrate with the AI Assistant.
Update reports automatically.
Work completely offline.
Synchronize automatically with Supabase.

6.4 Order States

Every order exists in exactly one state.

Draft
   │
   ▼
Confirmed
   │
   ▼
Completed
   │
 ┌─┴───────────┐
 │             │
Cancelled   Returned
Draft

Order is being created.

Inventory remains unchanged.

Confirmed

Order has been approved.

Inventory is reserved but not deducted.

Completed

Sale is finalized.

Inventory is deducted.

Revenue is recorded.

Reports update.

Dashboard refreshes.

Cancelled

Order is cancelled before completion.

Inventory remains unchanged.

No revenue is recorded.

Returned

Customer returns purchased items.

Inventory increases.

Reports update.

Revenue adjusts.

6.24 Error Handling

Possible errors:

Error	Recovery
Product unavailable	Choose another product
Stock insufficient	Save as draft or restock
Invoice generation failed	Retry generation
Email failed	Retry later
Sync failed	Queue for later
Database error	Restore latest valid state

The system should preserve the order whenever possible.

6.26 Developer Implementation Notes

Implementation guidelines:

Store all order data locally in SQLite first.
Use transactions to ensure inventory and revenue updates occur atomically.
Queue completed orders for background synchronization with Supabase.
Generate invoices from reusable templates supporting branding and localization.
Integrate Gmail for email delivery with user confirmation before sending.
Expose order events so the Dashboard, Reports, Inventory, and AI modules refresh automatically.
Design the order state machine to support future features such as partial shipments, partial payments, and partial returns without major refactoring.
6.27 Acceptance Criteria

The Orders & Invoice Management Flow is complete when:

Orders can be created, edited, and saved as drafts.
Inventory is deducted only when an order is completed.
Order totals are calculated accurately.
Professional invoices are generated with company branding.
Users are asked before invoices are saved and before they are emailed.
Gmail integration sends invoices successfully when approved.
Offline order creation works without data loss.
Synchronization with Supabase occurs automatically.
Order notifications open the related records.
AI provides contextual assistance without making irreversible changes automatically.
All order state transitions behave consistently and preserve data integrity.
6.28 Chapter Summary

The Orders & Invoice Management Flow defines the complete sales lifecycle within Co-op, from creating a draft order to generating branded invoices, updating inventory, recording revenue, and synchronizing with the cloud. By combining offline-first operation, AI-assisted workflows, automatic reporting updates, and secure synchronization, Co-op delivers a fast, reliable, and scalable order management experience suitable for growing businesses.
