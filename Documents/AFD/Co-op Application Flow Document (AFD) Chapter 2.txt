Chapter 2 — Application Lifecycle & Startup Flow
2.1 Purpose

This chapter defines everything that occurs from the moment a user launches Co-op until they arrive at the Dashboard.

The startup process is designed to:

Launch quickly
Restore the previous session automatically
Validate the user's authentication
Load local business data
Connect to cloud services
Synchronize changes in the background
Recover safely from crashes
Provide a seamless transition into the application

The entire startup experience should feel fast, reliable, and almost invisible to the user.

2.2 Startup Goals

The startup process should:

Launch in under 3 seconds under normal conditions.
Restore the previous session automatically after an unexpected shutdown.
Work whether the user is online or offline.
Avoid blocking the user while cloud synchronization occurs.
Load critical data before displaying the Dashboard.
Notify the user only if their attention is required.

2.5 Splash Screen

The splash screen serves two purposes:

Reinforce Co-op branding.
Hide initialization tasks from the user.

Displayed elements:

Co-op logo
Product name
Version number
Loading indicator

Example:

          Co-op

Better business, together

Version 1.0

Loading...

Maximum display time:

2 seconds

If initialization finishes earlier, transition immediately.

2.6 Initialization Sequence

The application initializes services in the following order:

Electron runtime
React application
Theme manager
Local configuration
SQLite database
Logging system
AI configuration
Network monitoring
Notification service
Synchronization service

Each service should initialize independently where possible to reduce startup time.

2.7 Authentication Check

After initialization, Co-op determines whether the user is authenticated.

Possible outcomes:

Authenticated

Continue to Dashboard.

Authentication Expired

Redirect to Login.

First Launch

Redirect to Account Creation.

Offline Authentication

If a previously authenticated session exists and has not expired, allow offline login using cached credentials.

2.10 Previous Session Restoration

If Co-op closes unexpectedly due to a crash or power loss, the application restores the previous session automatically on the next launch.

Restored items include:

Active page
Open dialogs (where possible)
Unsaved drafts
Search filters
AI conversations
Scroll positions

A notification informs the user:

"Your previous session has been restored successfully."

2.11 Local Database Initialization

SQLite is initialized before cloud services.

During initialization:

Open database
Verify schema
Run migrations if necessary
Load cached business data
Prepare offline queue

Failure to initialize prevents entry into the Dashboard.

2.12 Background Services

Once the Dashboard loads, background services start automatically.

Services include:

Cloud synchronization
Notification monitoring
AI connectivity checks
Auto-update checks
Network status monitoring
Error logging

Users should be able to work while these services initialize.

2.16 Error Recovery During Startup

If initialization fails, Co-op attempts automatic recovery.

Examples:

Database Error

Retry opening the database.
Offer to restore from the latest backup if recovery fails.

Network Error

Continue in Offline Mode.

Cloud Sync Failure

Queue synchronization for later.

Unexpected Error

Log the error.
Restore the last stable state where possible.
Present a retry option.

User-facing messages should be clear and avoid technical jargon.

2.17 Background Loading Strategy

The application prioritizes loading components in this order:

User interface shell
Dashboard layout
KPI widgets
Orders summary
Inventory summary
Customer summary
Reports preview
AI insights
Notifications

This ensures users can begin interacting with the application before all background data has loaded.

2.20 Acceptance Criteria

The startup flow is complete when:

Co-op launches in under 3 seconds under normal conditions.
Authentication behaves correctly online and offline.
Company setup appears only for first-time users.
Previous sessions are restored automatically after crashes.
Local data is loaded before cloud synchronization.
Background services initialize without blocking the user.
Offline mode functions correctly.
Startup errors are handled gracefully.
Performance targets are met across supported hardware.
2.21 Chapter Summary

This chapter defines the complete lifecycle from launching Co-op to reaching the Dashboard. The startup process prioritizes speed, resilience, and continuity by loading local data first, restoring previous sessions automatically, and performing cloud synchronization in the background. Whether online or offline, users can begin working quickly while Co-op transparently manages authentication, initialization, and recovery tasks.
