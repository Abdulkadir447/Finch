Chapter 14 — Notifications & Activity Schema
14.1 Purpose

The Notifications & Activity module is responsible for informing users about important business events while maintaining a complete timeline of actions performed throughout the application. It serves as the communication layer between Finch's backend services and the user interface.

This module integrates with every major subsystem including:

Orders
Inventory
Customers
Payments
Reports
AI Assistant
Synchronization
Security
Settings

Notifications help users react to business events in real time, while the Activity Timeline provides a permanent history of important actions for auditing, troubleshooting, and operational awareness.

14.2 Objectives

The Notifications & Activity module must:

Support in-app notifications.
Support desktop notifications.
Track read and unread states.
Support notification expiration.
Store activity history.
Support AI-generated alerts.
Support system announcements.
Support notification actions.
Synchronize efficiently.
Work offline.

14.23 Offline Behavior

The Notifications & Activity module fully supports offline operation.

Users can:

View cached notifications.
Read activity history.
Mark notifications as read.
Dismiss notifications.
View AI recommendations already stored locally.

Actions performed offline are synchronized automatically when connectivity is restored.

14.24 Developer Implementation Notes

Implementation guidelines:

Use UUIDs for all notification-related tables.
Separate notifications, delivery tracking, preferences, and activity logs into normalized tables.
Use a background worker to process the notification queue.
Automatically remove expired notifications according to retention settings.
Support actionable notifications by linking them to business records.
Cache recent notifications locally for fast access.
Protect all notification data using Row Level Security (RLS).
14.25 Acceptance Criteria

The Notifications & Activity Schema is complete when:

Both in-app and desktop notifications are supported.
Read and unread states function correctly.
Notifications respect user preferences.
Action buttons open the correct application page.
AI-generated alerts are displayed separately.
Activity history records all significant events.
Expired notifications are automatically removed.
Offline notification management synchronizes successfully.
All notification and activity data is secured by RLS and fully audited.
14.26 Chapter Summary

The Notifications & Activity Schema provides Finch with a centralized event communication system that keeps users informed while maintaining a comprehensive history of business operations. Through support for in-app and desktop notifications, AI-generated alerts, configurable preferences, actionable notifications, and a permanent activity timeline, the module enhances usability, accountability, and operational awareness. Its offline-first architecture, efficient synchronization strategy, and secure RBAC/RLS integration ensure reliability and scalability as Finch grows.
