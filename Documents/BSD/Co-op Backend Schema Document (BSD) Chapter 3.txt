Chapter 3 — Authentication Schema
3.1 Purpose

This chapter defines the authentication architecture for Co-op. Authentication is responsible for verifying user identity, protecting business data, managing user sessions, and providing secure access to all backend services.

Co-op uses Supabase Authentication as its identity provider while integrating with the local desktop application to provide a seamless offline-first experience.

The authentication system supports:

Email & Password authentication
Google Sign-In
Session management
Offline login
Multiple businesses per account
Future multi-user organizations
Secure synchronization
3.2 Objectives

The authentication system must:

Provide secure account registration.
Support Email and Google sign-in.
Verify email addresses.
Allow secure password recovery.
Support automatic login restoration.
Enable offline authentication using cached sessions.
Protect every API request.
Integrate with Row Level Security (RLS).
Support future enterprise identity providers.

3.8 Password Requirements

Passwords must contain:

Minimum 8 characters
At least one uppercase letter
At least one lowercase letter
At least one number
At least one special character

Passwords are never stored directly by Co-op; they are securely managed by Supabase Auth.

3.11 User Profile Schema

Every authenticated account has a corresponding profile.

Table: profiles
Column	Type	Description
id	UUID	Primary key (matches Supabase Auth user ID)
full_name	TEXT	User's full name
email	TEXT	Primary email address
avatar_url	TEXT	Profile image
phone_number	TEXT	Optional contact number
preferred_language	TEXT	Future localization support
timezone	TEXT	User's preferred timezone
created_at	TIMESTAMPTZ	Account creation time
updated_at	TIMESTAMPTZ	Last profile update

The profiles.id field references the authenticated user ID from Supabase Auth.

3.12 Session Management

Each authenticated session contains:

User ID
Access Token
Refresh Token
Device Identifier
Session Start Time
Last Activity Time

Sessions are refreshed automatically while the user remains active.

   │
   ├── Business A

3.19 Row Level Security (RLS)

Authentication integrates directly with PostgreSQL Row Level Security.

Every query must satisfy:

Authenticated user
Authorized business
Valid permissions

No business data is returned unless the user is authorized to access it.

Email verified

Login failed
Password reset requested

These events are written to the audit log for security and troubleshooting.

3.21 Error Handling
Error	User Response
Invalid email	Prompt to correct email
Incorrect password	Display generic authentication error
Email not verified	Prompt to verify email
Expired session	Redirect to login
Google authentication failed	Retry or choose another login method
Offline without cached session	Inform user that online login is required

Error messages should be informative without exposing sensitive information.

Operation	Target

3.23 Developer Implementation Notes

Implementation guidelines:

Use Supabase Auth as the sole identity provider.
Store additional user information in the profiles table, linked by the Supabase Auth user ID.
Cache authenticated sessions securely to support offline access.
Keep authentication logic separate from authorization and business logic.
Integrate authentication with RLS policies on all business-owned tables.
Never expose access tokens or refresh tokens to application logs.
Prepare the authentication layer for future OAuth providers and enterprise SSO.
3.24 Acceptance Criteria

The Authentication Schema is complete when:

Users can register using email and password.
Google Sign-In functions correctly.
Email verification is enforced.
Password recovery is secure.
Sessions restore automatically.
Offline login works with valid cached sessions.
Multiple businesses are supported per account.
Future role-based access is accommodated.
RLS protects all business data.
Authentication performance targets are met.
3.25 Chapter Summary

The Authentication Schema establishes the secure identity foundation for Co-op. By leveraging Supabase Auth, supporting both email and Google authentication, enabling offline session restoration, and integrating tightly with Row Level Security, the system provides a secure, scalable, and user-friendly authentication experience. This architecture also lays the groundwork for future enterprise identity providers, advanced access control, and multi-user collaboration while maintaining the offline-first philosophy of the application.
