Chapter 16 — Security, Authentication & Audit Schema
16.1 Purpose

The Security, Authentication & Audit module is the foundation of Finch's security architecture. It protects business data, manages user authentication, controls permissions, secures synchronization, and records every critical system event for accountability and compliance.

Finch is designed as a multi-tenant business platform, meaning each business operates in a completely isolated environment. Security is enforced at every layer—from the database to the user interface.

16.2 Objectives

The Security module must:

Authenticate users securely.
Support multiple businesses per user.
Enforce Role-Based Access Control (RBAC).
Protect all data using Row Level Security (RLS).
Secure API communication.
Maintain audit logs.
Register trusted devices.
Support secure session restoration.
Encrypt sensitive information.
Prepare for future Multi-Factor Authentication (MFA).

16.7 Password Security

Passwords are:

Hashed using Argon2id (preferred) or bcrypt.
Salted automatically.
Never recoverable.
Validated against minimum complexity requirements.

Password rules:

Minimum 12 characters.
Uppercase letter.
Lowercase letter.
Number.
Special character.

16.12 Row Level Security (RLS)

Every business table includes a business_id.

Example policy:

business_id = current_user_business()

This ensures:

Business A cannot access Business B's data.
Every query is automatically filtered.
Data isolation is enforced at the database level.
16.13 API Security

All API requests require:

HTTPS/TLS encryption.
Valid JWT access token.
Active session.
Business context.
Permission validation.

Unauthorized requests return appropriate HTTP status codes (401 or 403).

16.16 Encryption

Sensitive information is protected using:

TLS 1.3 for data in transit.
AES-256 encryption for selected sensitive data at rest.
Encrypted environment variables.
Secure storage for API keys and secrets.

Passwords are hashed, not encrypted.

Backup access is restricted to authorized administrators and automated services.

16.21 Synchronization Security

Synchronization is secured by:

JWT authentication.
Device validation.
Session verification.
RLS enforcement.
Encrypted transport.
Signed synchronization requests.

Synchronization requests are rejected if authentication or authorization fails.

16.22 Offline Security

While offline:

Local SQLite database remains encrypted where supported by the platform.
Cached credentials are stored securely using the operating system's secure storage mechanisms.
Sensitive actions still require local authentication if configured.
Pending synchronization data remains protected until uploaded.
16.23 Developer Implementation Notes

Implementation guidelines:

Use UUIDs for all security-related tables.
Hash passwords with Argon2id (or bcrypt if Argon2id is unavailable).
Use JWT access tokens with refresh token rotation.
Enforce RBAC before every protected operation.
Apply RLS to every business-owned table.
Store audit logs as append-only records.
Register trusted devices to improve security and usability.
Design the schema to support future MFA, SSO, and enterprise identity providers.
16.24 Acceptance Criteria

The Security, Authentication & Audit Schema is complete when:

Users authenticate securely using JWT-based sessions.
Passwords are securely hashed and never stored in plain text.
Multiple businesses per user are supported.
RBAC permissions are enforced consistently.
RLS isolates business data.
Trusted devices are tracked.
Sessions restore securely and regenerate tokens after full system restarts.
Security events and audit logs capture all critical actions.
Sensitive data is encrypted appropriately.
The architecture is ready for future MFA and SSO support.
16.25 Chapter Summary

The Security, Authentication & Audit Schema provides Finch with a robust security foundation built around secure authentication, role-based authorization, trusted device management, encrypted communications, and comprehensive auditing. By combining JWT-based session management, Row Level Security, multi-business isolation, immutable audit logs, and a future-ready architecture for MFA and SSO, Finch ensures that business data remains protected while supporting scalable growth from individual entrepreneurs to enterprise organizations.
