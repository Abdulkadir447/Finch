Chapter 6 — Layout System & Navigation
6.1 Purpose

This chapter defines the structural layout system and navigation framework used throughout Finch.

The goal is to create a desktop experience that is:

Fast
Predictable
Consistent
Space-efficient
Keyboard-friendly
Optimized for business productivity

The layout system is designed specifically for Windows desktop environments while maintaining enough flexibility for future platform expansion.

6.2 Design Goals

The layout system should:

Maximize available workspace.
Keep navigation accessible at all times.
Reduce unnecessary window changes.
Support multitasking.
Adapt to different monitor sizes.
Provide a consistent experience across all modules.
Minimize visual distractions.

6.19 Notification Placement

Toast notifications appear in the top-right corner.

The Notification Center opens from the title bar.

Notifications stack vertically and automatically dismiss after a configurable timeout unless user interaction is required.

6.23 Ultra-Wide Displays

On larger displays, Finch can display additional panels.

Examples:

AI Assistant alongside reports
Customer details while browsing orders
Expanded dashboards

Unused space should never feel empty.

6.24 Multi-Window Support

Version 1.0 supports:

Main application window
Print preview window
PDF preview window

Future versions may introduce detachable workspaces and multiple document windows.

6.25 Keyboard Navigation

Navigation shortcuts include:

Shortcut	Action
Ctrl + K	Command Palette
Ctrl + Shift + A	Open AI Assistant
Ctrl + N	New Order
Ctrl + P	Print
Ctrl + S	Save
Ctrl + /	Search
Alt + Left	Back
Alt + Right	Forward

Focus order should always be logical and visible.

6.26 Navigation Animations

Navigation transitions should be subtle.

Examples:

Sidebar expansion: 200 ms
Page fade/slide: 180–220 ms
Drawer open/close: 220 ms
Modal appearance: 180 ms
Toast notification: 200 ms

Animations should reinforce context without delaying user actions.

6.27 Empty Workspace Behavior

When no data exists:

Display an illustration.
Provide a brief explanation.
Offer AI suggestions.
Present a primary action button.

For example, an empty Orders page might suggest creating the first order and offer an AI tip on setting up products.

6.28 Layout Accessibility

The layout must support:

Full keyboard navigation.
Clear focus indicators.
Screen reader compatibility.
High-contrast mode.
Scalable interface elements.

No essential function should depend solely on mouse interaction.

6.29 Future Workspace Features

Planned enhancements include:

Dockable panels.
Custom dashboard layouts.
Saved workspaces.
Multiple workspace profiles.
Multi-window editing.
Plugin panels.
Workspace templates.

These features should integrate with the existing layout architecture without requiring a redesign.

6.30 Acceptance Criteria

The layout and navigation system is complete when:

Every module follows a consistent page structure.
Navigation remains accessible from every screen.
Sidebar behavior is smooth and predictable.
Split-view layouts support efficient workflows.
Floating AI integrates seamlessly without obstructing work.
The application adapts gracefully to different window sizes.
Keyboard navigation is fully supported.
Layout rules are reusable across all current and future modules.
Chapter Summary

This chapter defines the structural foundation of Finch's interface. A consistent window layout, expandable sidebar, modular page templates, and integrated navigation create a cohesive experience across the application. By emphasizing efficient workflows, responsive layouts, and accessibility, Finch delivers a desktop interface that supports productivity while remaining scalable for future features.
