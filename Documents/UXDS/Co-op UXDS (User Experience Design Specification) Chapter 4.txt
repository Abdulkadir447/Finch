Chapter 4 — Design Tokens & Visual Foundations
4.1 Purpose

This chapter establishes the visual foundation of Co-op by defining the core design tokens and styling rules that will be used consistently throughout the application.

Design tokens are the smallest reusable visual values that create a unified experience across every screen, component, and interaction.

This chapter ensures Co-op maintains a consistent, scalable, and maintainable design system while supporting both Light and Dark themes.

4.2 Design Philosophy

Co-op's visual identity is based on five principles:

Simplicity

Only essential elements should be visible.

Consistency

Every screen should feel like part of the same application.

Readability

Business information should always be easy to understand.

Efficiency

Visual styling should improve productivity rather than distract from it.

Premium Quality

Every detail should communicate polish, trust, and professionalism.

4.3 Design Language

Co-op combines visual ideas from:

Linear
Cursor
Arc Browser
Notion
Microsoft Fluent
VS Code

The result is a clean, modern desktop interface optimized for business productivity.

4.4 Theme System

Co-op supports two themes:

Light
Dark

Theme selection follows the Windows system preference by default.

Users may manually override the theme in Settings.

Theme changes should occur instantly without restarting the application.

4.5 Brand Identity

Brand Name:

Co-op

Tagline:

Better business, together.

The official branding, logos, and color palette are defined in the project's design.md file, which serves as the authoritative source for visual identity.

All UI elements must align with this branding.

4.6 Color System

Co-op uses a semantic color system rather than assigning meaning to fixed colors.

Core Color Roles
Token	Purpose
Primary	Main accent color (from design.md)
Secondary	Supporting accent
Background	Main application background
Surface	Cards, panels, dialogs
Surface Elevated	Floating windows
Border	Dividers and outlines
Text Primary	Headings and important content
Text Secondary	Supporting information
Text Disabled	Inactive elements
Success	Positive actions and confirmations
Warning	Alerts requiring attention
Error	Validation errors and failures
Info	Informational messages

The actual color values are defined centrally and should never be hardcoded into components.

4.7 Light Theme

Characteristics:

Bright workspace
High readability
Soft shadows
Neutral backgrounds
Subtle contrast

Guidelines:

Use accent colors sparingly.
Avoid heavy borders.
Maintain generous whitespace.
Prioritize readability.
4.8 Dark Theme

Characteristics:

Comfortable for long working sessions
Low eye strain
High contrast text
Layered surfaces
Soft shadows

Guidelines:

Avoid pure black backgrounds.
Use elevation through subtle contrast.
Maintain accessible text ratios.
4.9 Typography

Typography should prioritize clarity and readability.

Recommended font stack:

Inter
↓
Segoe UI
↓
System UI
↓
Sans-serif

Inter is preferred due to its excellent readability for dashboards and data-heavy interfaces.

4.10 Typography Scale
Style	Weight	Usage
Display	Bold	Welcome screens
H1	Bold	Page titles
H2	SemiBold	Section titles
H3	Medium	Card titles
Body Large	Regular	Primary content
Body	Regular	General content
Body Small	Regular	Supporting text
Caption	Medium	Metadata
Label	Medium	Forms
Button	SemiBold	Buttons
Mono	Regular	IDs, invoice numbers, technical values
4.11 Spacing System

Co-op follows an 8-point spacing system.

Spacing tokens:

Token	Value
XS	4px
S	8px
M	16px
L	24px
XL	32px
XXL	48px
XXXL	64px

This ensures consistent spacing throughout the application.

4.12 Grid System

Primary layout:

12-column responsive desktop grid

Rules:

Equal column widths
Consistent gutters
Adaptive resizing
Maximum content width where appropriate

Dashboard cards align to this grid.

4.13 Corner Radius

Rounded corners reinforce Co-op's modern appearance.

Recommended tokens:

Token	Radius
Small	6px
Medium	10px
Large	14px
Extra Large	20px
Pill	999px

Consistency is more important than variety.

4.14 Borders

Borders should be subtle.

Use borders only to:

Separate content
Define inputs
Highlight focus
Indicate selection

Avoid unnecessary outlining.

4.15 Shadows & Elevation

Co-op uses shadows to communicate depth.

Elevation	Usage
Level 0	Background
Level 1	Cards
Level 2	Dropdowns
Level 3	Modals
Level 4	Floating AI
Level 5	Notifications

Shadows should remain soft and unobtrusive.

4.16 Icons

Icon style:

Outlined
Modern
Consistent stroke width
Minimal detail

Primary icon library:

Lucide Icons

Fallback:

Ant Design Icons

Icons should remain recognizable at small sizes.

4.17 Illustrations

Illustrations are used for:

Empty states
Onboarding
Error pages
Success confirmations

Style:

Flat
Minimal
Friendly
Brand-aligned

Illustrations should support—not distract from—the content.

4.18 Imagery

Photography is used sparingly.

Allowed:

Company logos
Customer avatars
Product images
QR codes

Avoid decorative stock photography in the main application.

4.19 Motion Tokens

Animations should be fast and smooth.

Type	Duration
Instant	100 ms
Fast	150 ms
Standard	200 ms
Slow	300 ms
Large Transition	400 ms

Ease curves should feel natural and responsive.

4.20 Animation Principles

Animations should:

Reinforce user actions.
Guide attention.
Preserve context.
Never delay interaction.

Examples:

Sidebar expansion
Hover effects
Dialog appearance
Toast notifications
AI panel transitions
4.21 Opacity Tokens

Opacity levels:

Token	Usage
100%	Primary content
80%	Secondary content
60%	Disabled text
40%	Placeholders
20%	Hover overlays
10%	Background accents
4.22 Blur Effects

Blur is used sparingly.

Appropriate use:

Floating AI Assistant
Modal overlays
Context menus
Dropdown menus

Blur should enhance focus without reducing readability.

4.23 Z-Index Hierarchy
Layer	Purpose
Background	Base application
Content	Main UI
Sticky Header	Page headers
Sidebar	Navigation
Dropdown	Menus
Tooltip	Hover information
Modal	Dialogs
Floating AI	Assistant
Notification	Toasts
Critical Overlay	Blocking dialogs

This hierarchy prevents visual conflicts.

4.24 Component States

Every interactive component must define:

Default
Hover
Focus
Active
Selected
Disabled
Loading
Error
Success

State transitions should be animated consistently.

4.25 Accessibility Tokens

The visual system must support:

WCAG 2.1 AA contrast ratios.
Visible keyboard focus indicators.
Color-independent status indicators.
Scalable typography.
Consistent interactive targets.

Accessibility is a first-class requirement, not an optional enhancement.

4.26 Design Token Naming Convention

Design tokens should follow a structured naming format.

Examples:

color.primary
color.surface
color.success
text.primary
text.secondary
spacing.md
radius.lg
shadow.level2
motion.fast
opacity.disabled

This convention improves maintainability and developer handoff.

4.27 Developer Integration

Design tokens should be implemented as reusable variables and consumed consistently across the application.

They should integrate with:

Tailwind CSS theme configuration
Ant Design theme customization
Shared TypeScript constants (where applicable)

All styling should reference the design tokens rather than hardcoded values.

4.28 Acceptance Criteria

The visual foundation is considered complete when:

Light and Dark themes are fully defined.
Branding aligns with design.md.
Typography, spacing, colors, and elevation are standardized.
Motion and interaction timings are consistent.
Design tokens are reusable across the application.
Components rely exclusively on the shared design system.
Accessibility requirements are met.
Chapter Summary

This chapter establishes the visual language and reusable design tokens that define Co-op's appearance. By standardizing colors, typography, spacing, elevation, motion, and accessibility, Co-op achieves a cohesive and scalable design system. These foundations ensure every screen and component delivers a polished, premium experience while simplifying implementation and long-term maintenance.
