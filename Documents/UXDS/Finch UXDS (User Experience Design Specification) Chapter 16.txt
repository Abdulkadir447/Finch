Chapter 16 — Global Components & Design System
16.1 Purpose

The Global Components & Design System defines the visual language, interaction patterns, reusable UI components, and design tokens that make Finch feel like one cohesive product.

Rather than treating every page as a separate interface, every screen—from Dashboard to AI Assistant—must share the same design principles, spacing, animations, colors, typography, and interaction behaviors.

The Finch Design System is inspired by the quality of modern desktop software such as:

Linear
Notion
Arc Browser
Microsoft Loop
Apple Human Interface
Ant Design Pro
Raycast
Cursor IDE
GitHub Desktop

The goal is to create a premium desktop application that feels native to Windows while maintaining its own recognizable identity.

16.2 Design Philosophy

Every interface in Finch follows six principles:

Elegant

Minimal without looking empty.

Functional

Every UI element exists for a reason.

Fast

Animations never delay productivity.

Intelligent

The interface should proactively help users.

Consistent

Every screen follows identical spacing and behaviors.

Beautiful

Business software should feel enjoyable to use.

16.3 Design Tokens

Every visual value should come from centralized design tokens.

Never hardcode colors, spacing, border radius, or typography.

Example:

--color-primary
--color-success
--spacing-md
--radius-lg
--shadow-card

This enables complete theme customization.

Guidelines:

Token	Value
XS	4 px

MD	16 px
LG	24 px

16.10 Shadows & Elevation

Use layered shadows instead of heavy drop shadows.

Elevation levels:

Level	Usage
0	Background
1	Cards
2	Dropdowns
3	Floating AI Panel
4	Dialogs
5	Critical Modals

Dark mode uses softer, lower-opacity shadows.

16.25 Accessibility Standards

Every component must support:

WCAG 2.2 AA compliance
Keyboard navigation
Screen readers
High contrast mode
Focus indicators
200% zoom
Reduced motion settings
Minimum touch target of 44 × 44 px (for touch-capable devices)

Accessibility is a core requirement, not an optional enhancement.

16.26 Responsive Desktop Behavior

Although Finch is a desktop-first application, it should adapt gracefully to different window sizes.

Supported layouts:

Width	Behavior
≥1600 px	Wide layout with additional panels
1200–1599 px	Standard layout
900–1199 px	Compact layout with collapsible panels
<900 px	Minimum supported width with simplified layout

Users should be able to resize the application without breaking the interface.

16.28 Developer Implementation Rules

All shared components must:

Be reusable across modules.
Be fully typed with TypeScript.
Support Light and Dark themes.
Follow Ant Design patterns where appropriate.
Be responsive within supported desktop sizes.
Include loading, empty, and error states.
Support keyboard navigation.
Be independently unit tested with Vitest.
Be documented in Storybook (recommended for internal development).
16.29 Acceptance Criteria

The Global Components & Design System is considered complete when:

All UI components use shared design tokens.
Typography, spacing, colors, and icons are consistent across the application.
Every component supports Light and Dark themes.
Reusable components eliminate duplicate implementations.
Motion and animations follow the defined timing guidelines.
Accessibility requirements meet WCAG 2.2 AA standards.
Components are fully documented and reusable by developers.
The application presents a polished, premium, and cohesive visual identity.
Chapter Summary

The Global Components & Design System is the foundation of Finch's user experience. By standardizing colors, typography, spacing, components, motion, and accessibility, it ensures that every screen feels unified, intuitive, and professional. This design system enables faster development, easier maintenance, and a consistent experience as Finch grows with new features and future releases.
